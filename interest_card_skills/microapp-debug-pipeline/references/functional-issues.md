# 功能：输入/动作/截图 → handler/状态/接口 → 修复 → 原路径结果

本文件只处理交互、播放/生成、结果、保存、跳转与卡页状态问题。输入分析、页面识别、执行顺序与交付见 [debug-workflow.md](debug-workflow.md)，玩法、命名和准入分流见 [SKILL.md](../SKILL.md)。

## 检查操作

- 有截图先分析其中的控件、输入和可见结果，再定位对应 handler、状态与接口；截图不能证明按钮已经点击、请求已完成、结果已保存或卡页已互通。补一次真实原路径操作。
- 固定一个 Case：`前置状态 → 输入/动作 → 预期 → 实际结果`。保留动作前后截图、正文、真实路由，以及自然产生的请求/错误/保存回执；区分未操作态、加载态和最终态。

| 功能现象 | 优先定位 | 核心验证 |
| --- | --- | --- |
| 点击/输入无反馈、无法提交 | handler、覆盖层、disabled/loading、异步异常 | 真实命中正确控件后是否产生约定结果，而非只有按压动画 |
| 播放无声、进度不动、生成仅显示回退 | 资源 URL、真实请求、媒体/生成回调和失败信息 | 实际播放/生成是否完成，可见状态是否与真实回调或结果一致 |
| 未操作即出结果、结果错误、重复计分、固定假榜 | 初始化、输入映射、计算规则、缓存与用户 key | 核对未操作态与结果来源，两组有区别的真实输入按规则结算，重进后不把历史结果当本轮结果 |
| 图片/内容数据缺失或显示旧值 | 请求参数、响应 schema、字段映射、状态更新与渲染条件 | 响应、组件收到的字段、最终可见结果是否一致 |
| 跳转失败、卡页状态不一致 | CTA、注册路由、对象 key、保存回执、首读初始化 | bridge、实际落地路由和状态承接独立判断 |
| 页面错误、loading 不结束、重试不恢复 | 真实错误请求、异常边界、loading 生命周期 | 按请求完成与稳定正文确认最终结果，不截短暂 loading 冒充恢复 |
| 已约定能力缺失、卡面任务被拆分、权益未兑现 | 用户已确认需求/设计、承诺文案与实际核心路径 | 确认卡面完成已约定动作与结果，落地延伸同主题内容；区分实现偏离与需要重新设计的产品缺口 |
| 涉及 TT API 的授权、保存、定位、媒体或网络能力 | 实际 JSAPI/SDK 调用、当前应用身份、隐私协议、域名类型与能力开通 | 按 [platform-config.md](platform-config.md) 核对适用项，不限真机报错或已发生失败；异常时结合真实回调定位 |

- 结果问题按 `首次进入 → 未操作态 → 实际输入与结算 → 保存 → 重进` 检查适用阶段。先保留现有记录，再通过产品已有重置/再来一次入口开始本轮；没有该入口时按验证边界准备本地前置，不清空他人或来源不明的数据。
- 沿展示字段追到计算、响应、缓存或 seed，区分本轮结果、历史最佳、示例和本轮测试数据。两组输入按明确规则验证，不能要求结果必然不同，也不能把已约定的娱乐随机判为不客观；规则不明确时待确认，不自行改评分算法。
- 排行榜核对真实数据来源、用户 key、排序与更新条件；同一用户的历史最佳未提高时排名不变可能正常。不注入假用户证明排名变化；无法在当前真实数据下验证的分支保持 blocked。本轮测试结束只清理已明确归属且允许清理的数据。
- 从失败控件逐层追到 `handler → 状态 → 请求/计算 → 渲染/保存`，只查有证据指向的层。不直接执行 handler、dispatch 伪事件或用接口写入最终结果代替真实操作。
- readiness 已成功但业务 frame 空白时，先查该 frame 的页面脚本与请求，区分终态业务错误、静态脚本 4xx/5xx 与宿主初始化丢失；不要只等正文或反复重载。保留真实错误，修正入口或恢复后有界重试一次。
- 可用当前沙盒本地接口准备或清理前置数据；保留实际输入与回执，不注入假用户、假榜单或伪造成功。
- 状态互通问题先保存 Card Final 与保存回执，通过真实 CTA 打开落地，在任何同类写入前保存首个稳定 First Read。按已确认 same/mapped 关系对账，不机械要求本局分数等于历史最佳；跨 origin localStorage 不共享不是设计豁免。
- 请求、字段和状态已正确但最终显示仍异常时，再读 [ui-issues.md](ui-issues.md) 核对布局、裁切和资源显示，不改正确数据来迁就错误 UI。

## 修改操作

- 修具体事件绑定、状态初始化/更新、计算、字段映射、请求契约、错误反馈或路由；涉及卡页共享语义时同步相关两端。
- 播放/生成问题修真实资源或调用链，按当前 SDK 契约更新状态；不立即置成功、不用定时器模拟播放进度，不把回退图当生成成功。原生能力或域名/权限问题按真实错误分流，不改身份绕过。
- 需要 Canvas 导出、原生跳转或授权契约时，按需读取同级生成 Skill 的对应规范与当前 SDK 文档，不用其他平台的类型签名或社区旧答复替代。有加载卡死时逐阶段核对初始化、资源、导出、保存的回调与 loading 收口，不把下载/预览图片当作保存相册成功。
- 承诺落空先修已有链路的实现偏离；需要新增核心功能、重设玩法、重新分配卡页职责或改变权益门槛时，按 `SKILL.md` 转设计/生成，保留未解决项，不仅修改承诺文案来掩盖缺功能。
- 保留原需求，不删按钮、固定结果、造假排行、额外跳转或仅改承诺文案来掩盖缺功能；不擅自统一 AppId、OPEN_CARD_ID 或 runtime。
- 需要重设玩法、经营内容或准入方案时先确认。原生能力无法在浏览器验证、规则缺失或素材不可得时记 blocked，不编造替代成功。

## 复验操作

- 重走同一前置、输入、控件与动作；核对修后真实业务结果、相关请求/保存回执及新 PNG。截图证明可见反馈，请求/状态证明业务正确，不能互相替代。
- 结果修复复验未操作态、本轮结算、适用的保存/重进与重复操作，确认本轮只结算一次、历史语义未被破坏；排行榜按真实排序和更新条件验收，不强求排名变化。
- 补一条受影响的相邻正常分支，以及适用的空输入、重复操作、返回/重进或已有重试；正常路径未发生异常不代表容灾已覆盖。
- 卡页问题分别记录 CTA 和 stateHandoff；缺首读、保存回执或实际目标路由时保留 blocked。重试结束后必须有正确结果，不只检查错误词消失。
- 卡内 CTA、外壳 CTA 分别记结果，后者通过不能替代前者原生跳转验收。AI 生图失败与回退展示分别验收；回退可见不等于生成成功，按实际模型契约/错误定位，不猜权限或更换身份绕过。
