# TT API：隐私协议、域名白名单与应用身份

涉及 TT API（包括通过 Taro/SDK 调用）的授权、保存、定位、媒体或网络能力时，优先核对隐私声明、能力开通与域名白名单，应用身份放在后面按异常线索检查，不限真机报错，也不要求先出现失败。不涉及的配置项不检查，不展开全量配置审计。配置规则沿用当前系统提示词与生成 Skill；这里负责排障顺序、真实证据和安全增量操作。

按实际调用和当前官方文档/SDK 契约核对，不凭错误关键词猜根因。

## 1. 隐私声明与能力开通

1. 使用 `microapp_get_user_privacy_setting` 查询当前目标 AppId 的现有声明。
2. 使用 `microapp_get_user_privacy_items` 获取当前可选项及 Id，按实际方法/scope 和官方规范匹配；不硬编码 Id。
3. 对照当前提示词的 JSAPI 映射：保存相册对应「相册」；`chooseImage` 对应「相机」与「相册」；录音、定位、剪切板各检查对应项。只有「用户昵称、头像」兜底项不能覆盖这些能力。
4. `showDouyinOpenAuth` 等开放授权还需核对 scope 合法性、能力开通及相应隐私声明；例如账号数据类 scope 应核对「抖音账号数据」，不能将所有开放 scope 一律归到该项。

错误码只按该方法当前官方表反查。`showDouyinOpenAuth` 的 `117479` 指向隐私 scope 未声明、`117405` 指向无已开通 scope、`117490` 指向用户拒绝；其它方法或基础库的 `21104/21105/102xx` 不机械套用，`auth/deny/privacy` 字样也不能单独证明漏配。能力未开通和用户拒绝不能靠改 scope、伪造身份或强制授权解决。

补配已获明确授权时，按 `microapp_add_user_privacy_setting` 当前 schema 调用：保留全部既有隐私项、申请描述和联系方式，仅添加确实缺少的项；要求完整列表的接口先按 Id 合并去重，不能仅提交本项目使用的子集。写入后重新查询，确认新增项存在且原项未丢失。配置变化单独列入交付，不自动提交审核或发布。

未获授权、身份不一致、配置不可读或工具不可用时，给出具体缺项和平台功能/技术支持入口，相关检查或补配保持 blocked；不编造联系人、邮箱或回执。

## 2. 域名白名单

先用 `microapp_get_domain` 查询当前应用配置，沿真实前端调用追到最终 URL/host 与请求类型，包括重定向后的资源域名；不把 H5 代理或本地 HTTP 200 当作域名白名单已配置。

| 实际前端调用 | 核对类型 |
| --- | --- |
| `request`；`createInnerAudioContext` 设置远程 `src` | request |
| `downloadFile`；`getImageInfo`；`getBackgroundAudioManager` 使用远程资源 | download |
| `uploadFile` | upload |
| WebSocket JSAPI | socket |

同时核对协议、资源可访问性和方法实际错误，不能见 `src protocol is invalid` 就先改环境识别。普通组件 `src` 资源、纯服务端请求和沙盒 localhost 不因本规则自动添加域名；WebView 等场景按自己的当前契约检查。

确需新增且已获授权时，用 `microapp_add_domain` 逐域、逐实际类型添加，每次一个域名，保留既有白名单；禁止 `microapp_update_domain` 整表覆盖。重新查询确认，不重复添加已存在项，不用通配或关闭校验绕过。交付说明「已新增 / 已核对无需变更 / 未获授权未变更」及具体类型。

## 3. 应用身份（按异常线索检查）

- 工具返回 `AppID 错误`、应用名称/归属与项目不一致，或多个项目共用同一 AppId 时，再核实应用身份和配置作用域。
- 从当前沙盒 `APP_ID`、`OPEN_CARD_ID`、项目配置及对应工具回执核对目标。会话 cid、运行容器 cid、小程序 AppId 与兴趣卡 CardAppId 不互换，不改用记忆里的另一个 AppId 试写。
- 排查顺序后置不改变写入边界：任何平台配置补配前仍须确认目标归属与授权；共享配置只读，明确影响范围后再补配。
