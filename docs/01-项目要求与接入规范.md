## 一、 真实技术架构与接入链路（严禁偏离）

### 1.1 官方一体双端工程形态（`card-app/`）
抖音 AI 工坊的真实底层并非“单文件 H5 粘贴”，而是 **基于 `Taro + React + NestJS`（`pnpm` 管理依赖）的一体化工程 `/workspace/project/card-app`**：

| 产品层级 | 对应源码目录 | 渲染引擎与运行环境 | 硬性工程边界 |
| :--- | :--- | :--- | :--- |
| **兴趣卡（Feed 卡）** | `card-app/opencard/src/` + `feed/feed-card.json` | **Taro TSX 语法 + 字节 `Lynx` 原生渲染引擎** | **严禁纵向滚动、严禁 `@media`**；核心内容必须在 **`300px` 和 `436px` 两档槽高** 下完整可读无裁切；保留模板 `.widget-root`（半透明圆角面板）与 `.widget-body`（唯一 Actual FMP 标记）；不重复宿主标题与同语义入口；拖拽/陀螺仪受限。 |
| **兴趣卡落地页** | `card-app/src/` | **常规 Taro + React 抖音小程序页面** | 自由度高，支持完整小程序组件、Canvas 2D/WebGL（`@open-dy/threejs`）、多状态交互；图标统一用 `@open-dy/lucide-taro`（`opencard` 不装该包）。 |
| **开放域服务端** | `card-app/server/` | **NestJS 服务端** | 提供卡片首屏/交互接口 `/api/dy_card/data`（`resolveCardData()`）及落地页动态接口；生产依赖必须写入 `server/package.json` 的 `dependencies`。 |
| **封闭域服务端** | `card-app/closed-domain-server/` | **独立隔离 NestJS 服务** | 仅在命中高敏用户态 OpenAPI 时启用；普通娱乐/工具玩法走开放域 `server/` 即可。 |
| **宿主外框与路由** | `feed/feed-card.json` + `config/card-routing.json` | **抖音推荐流 / 个人页宿主外壳** | `PageIndex` 与 `PageURL` **严禁以 `/` 开头**（如写 `pages/index/index`）；背景音乐 `BgMusicUrl` **必填且仅配在 `feed-card.json` 由宿主播放**，严禁在卡代码里自实现 BGM；编译产物 `dist-tt` 与 `opencard/dist` 包体均须 `<= 16 MB`。 |

### 1.2 「外部 SOTA 开发 → 上传抖音 AI 工坊」标准交接链路
1. **外部开发分工**：
   - 在本仓库用外部 SOTA 模型（Codex `gpt-6.2-sol` / `gpt-6.2-astra` + Gemini 审美微调）阅读 `interest_card_skills/` 规范，打磨 `card-app/` 中的核心玩法、视觉界面、`DESIGN.md` 与 `server/` 业务逻辑。
   - **严禁臆造平台接口**：涉及抖音用户身份（`open-data` / `tt.getUserProfile`）、服务端 OpenAPI（`@open-dy/ai_coding_sdk/openapi`）、平台内置大模型（`ai-platform-llm-skill`）、云数据库（`init_douyin_cloud_mysql_*`）与图片转存（`transfer_file`）时，**在代码中用清晰的本地 Mock 兜底并标注 `// [PLATFORM-INTEGRATION]` 接入点**，绝不凭空猜测未公开 SDK 方法名，也**禁止编写 `Taro.getEnv() === WEB` 等浏览器 DOM 降级分支**。
2. **打包精简交接物（`pnpm run handoff`）**：
   - **绝对禁止整包上传**（不可把本地 `package.json`、`pnpm-lock.yaml`、`node_modules`、构建产物、密钥或模板基础配置打进压缩包，否则会覆盖损坏平台自带模板骨架、网络封装和 FMP 标记）。
   - 生成 **`dist/handoff.zip`**（仅含与 `card-app/` 同层级的业务源码、`DESIGN.md`、待转存素材及合并清单 `README.md`）+ **`dist/HANDOFF_PROMPT.md`**（含 8 项交接要素的平台 AI 提示词）。
3. **回平台自动接入与上线**：
   - 在抖音 AI 工坊对话框上传 `handoff.zip` 并发送 `HANDOFF_PROMPT.md` → 平台 AI 在既有模板上合并业务文件、接入真实抖音能力与大模型、转存图片为线上链接、配置 `feed-card.json` 背景图与 BGM → 平台预览器核对 `300/436` 卡面与落地页 → 补齐发布信息，提交审核并查看上线状态。赛道一须另按每张卡填写抖音参赛问卷；资料、时间与可选传播奖见[现行参赛决议](./07-牛顿哭了3D-最终定案立项决议书.md)。

## 二、 赛事业务与交互生死红线（内部最高否决权）

1. **永久排除方案（严禁复辟）**：
   - 永久拉黑《这句怎么回 / 社恐嘴替 / 嘴替接线员》及一切“读聊天文字气泡 + 打字输入框”类方案（已隔离在 `archive/deprecated-mouthpiece/`）。
2. **4 条「极速轻快」交互铁律**：
   - **零阅读负担（Seeing > Reading）**：单屏字数极简化，靠图形、视觉突变、物理反馈在 `0.2–0.5s` 秒懂，绝不让用户读段落。
   - **全程零软键盘（Zero Keyboard，含落地页 `src/`）**：`opencard/src/` 与 `src/` 严禁以 `<Input>` / `<Textarea>` 文本输入作为玩法入口；若调用平台 AI（`ai-platform-llm-skill`），一律采用**零打字图形槽位/图标点选参数**驱动后台结构化生成！
   - **Pure-Tap `<100ms` 爽感**：严禁 `<Slider>` 横滑条、任何时长的长按交互（含蓄力）或卡内纵向滚动；所有点按提供即时视觉弹性反馈。
   - **纯粹消费品界面**：UI 只呈现好玩的产品元素；面向用户及设计稿只使用「兴趣卡」「兴趣卡落地页」，绝不暴露内部技术词或调试台。
3. **「兴趣卡 → 落地页」双层价值切分（最终锁定主方向：《牛顿哭了 3D》）**：
   - **兴趣卡（`opencard/src/`）**：贴合 Lynx 无滚动、`300/436` 双档高度与 Canvas 禁绑触摸事件特性，采用高帧率 2.5D 分层舞台 + 外部 3 颗 `onClick` 违禁物理胶囊，开场 `0.9s` 演绎「胖橘推冰美式滑向盘沿」压哨救场，`<100ms` 即时压扁回弹拿满爽感，绝不截断结果骗点击。
   - **落地页（`src/` + `server/`）**：承接 `@open-dy/threejs` 首帧常驻 60fps 3D 微缩玩具盒、四大生活翻车场景×商业实验品换皮、零键盘「三槽 AI 炼金台 + 活体 AI 行为读心导演与反制」、12 种双法则化学反应图鉴、好友「崩盘前半秒」异步接力拆弹与模块化省队榜/纯净录屏！
   - **独立旗舰宣传演示站（`promo/`）**：与 `card-app/` 根级物理隔离、零外网依赖，供路演大屏、双模 AI 编译演示与爆款短视频录屏产粮；历史物理算法参考保留于 `refs/rebel-chopsticks-html-proto/`。
