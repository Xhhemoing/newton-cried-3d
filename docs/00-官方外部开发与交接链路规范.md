# 兴趣卡外部开发链路：用外部 SOTA 模型完成作品，再上传至抖音 AI 工坊（官方原文完整归档）

> **来源链接**：`https://bytedance.larkoffice.com/docx/UKOudehUPomQqexRcGGcdZ9BnDc?from=vcFollow`  
> **配套官方 Skill 包**：已完整解压至仓库根目录 [`interest_card_skills/`](../interest_card_skills/README.md)

---

## 核心思路

创作复杂玩法或高表现力的兴趣卡时，不必把所有生成与调试都放在平台内完成。创作者可以先在 Claude Code、Codex、Cursor 等外部工具中，调用外部 SOTA 模型把核心作品打磨成熟，最后再带回平台完成接入与上线。

1. **外部开发**：基于 AI 工坊相同的技术规范架构（加载 `interest_card_skills/`），在外部 AI 工具中反复打磨玩法、视觉、动效与后端逻辑。
2. **打包交接**：只把核心业务代码与素材打成精简压缩包 `handoff.zip`，并让外部 AI 生成一段交接提示词。
3. **回平台上线**：将压缩包和交接提示词发给抖音 AI 工坊，由平台 AI 自动接入抖音能力、转存资源并发布上线。

## 01｜为什么可行：共用同一套开发规范（Skill）

抖音 AI 工坊的创作助手，与 Claude Code、Codex、Cursor 等主流 AI 编程工具采用了相同的 Agent 工作机制：模型在一个工程目录里读写文件、执行命令，并在动手前按需读取 `.agent/skills/` 目录下的规范文件。

平台内置的兴趣卡 Skill 主要包含以下模块（外部精简版已解压至 `interest_card_skills/`）：
- **`microapp-generate-interest-card`（主流程规范）**：规定项目的工程结构、前后端数据格式、网络请求方式和运行检查项。
- **`design-skill`（视觉设计规范）**：指导界面排版与视觉风格，并产出 `DESIGN.md` 作为设计基准。
- **`microapp-capability-guide-interest-card`（平台能力说明书）**：说明可调用的抖音客户端 API、组件和服务端 OpenAPI 的检索与调用方式。
- **`microapp-optimize-interest-card` / `microapp-debug-pipeline`（优化与排障规范）**：负责图片资源处理、性能优化与发布失败常见代码问题排查。

## 02｜怎么分工：哪些在外部做，哪些回平台做

拆分原则：**需要高上限模型和反复试错的部分放在外部；必须依赖抖音环境和线上资源的部分留给平台。**

| 环节 | 在哪做 | 具体内容与原因 |
| :--- | :---: | :--- |
| **玩法与交互逻辑** | **外部** | 多分支机制、可玩微互动、复杂动效等核心玩法，可在外部自由迭代和反复调试 |
| **界面与视觉素材** | **外部** | 结合外部生图模型与前端组件，做出更细腻的卡面与视觉表现 |
| **服务端业务逻辑** | **外部** | 抽签、计分、状态流转等后端逻辑写在开放域服务（`server/`）中，先在本地把接口调通 |
| **基础工程模板** | **平台** | 底层模板骨架、网络请求模块、首屏性能（FMP）标记与路由配置，**直接沿用平台自带版本** |
| **抖音能力接入** | **平台** | 用户身份识别、客户端 API、OpenAPI、平台大模型（`ai-platform-llm-skill`）等能力，回到平台环境中再真实接入 |
| **线上资源与卡片外框** | **平台** | 将本地图片转存为线上 CDN 链接（`transfer_file`），生成信息流卡片的标题、背景图、背景音乐（`BgMusicUrl`）等外框配置 |
| **最终预览与发布** | **平台** | 在平台预览器中核对实际效果，补齐名称/图标/简介后提交上线 |

## 03｜外部开发：加载平台 Skill 完成核心作品

### 1. 标准工作文件夹结构
- 根目录放置解压出的 `interest_card_skills/`；
- 参考图、生图素材或现成前端原型组件放入 `refs/` 子文件夹备用；
- 正式项目工程目录为 `card-app/`（对应平台沙盒路径 `/workspace/project/card-app`）。

### 2. 与抖音 AI 工坊一致的工程结构
```text
card-app/
├── opencard/src/            # 信息流兴趣卡界面（Taro 语法，由 Lynx 引擎渲染）
├── src/                     # 点击卡片后进入的落地页（常规 Taro + React 页面）
├── server/                  # 开放域后端服务（NestJS），提供卡片数据接口 /api/dy_card/data
├── closed-domain-server/    # 封闭域后端服务（仅在涉及用户高敏感数据时使用）
├── feed/feed-card.json      # 卡片外框配置：标题、按钮、落地页入口、背景图、BGM、卡片 ID
├── feed/custom-card-schema.json
├── config/card-routing.json # 路由配置：记录服务类型（开放 / 封闭域）与展现形态（feed / post）
└── DESIGN.md                # 视觉设计规范
```

### 3. 两项关键外部开发约束
1. **信息流卡片由 Lynx 引擎渲染，限制较多，复杂内容尽量放进落地页**：
   - `opencard/src/` 只支持部分基础 CSS——**不能纵向滚动、不支持 `@media`，且核心内容必须在 `300` 和 `436` 两档高度下完整显示**；拖拽、陀螺仪等复杂手势受限。
   - 点击进入的落地页（`src/`）是常规 Taro + React 页面，自由度高得多，卡片放不下的复杂内容放到落地页承接。
2. **抖音专属能力先留好接入点，用本地数据兜底，严禁臆造平台接口**：
   - 用户身份、客户端授权、平台 OpenAPI、平台内置 AI 模型（`ai-platform-llm-skill`）在外部环境无法真实调通；先用本地模拟数据跑通流程，并在代码里标清接入位置，留给平台 AI 补齐，**绝不让外部 AI 凭空编造平台 SDK 方法名或参数**。

### 4. 官方开工提示词模板
```text
请先完整阅读当前文件夹下 interest_card_skills/ 中的 Skill 规范，重点阅读 microapp-generate-interest-card 和 design-skill。
请严格按规范中的目录结构搭建项目（参照 card-app/：opencard/src 兴趣卡、src 落地页、server 开放域服务、feed 宿主外框配置、config 路由配置、DESIGN.md 视觉规范），技术栈使用 Taro + React + NestJS，用 pnpm 管理依赖。

【开发要求】
1. 兴趣卡严格遵守 Skill 中的 Lynx 样式约束：不用 @media、不纵向滚动，确保在 300 和 436 两档高度下都能完整显示核心内容；落地页按常规页面实现。
2. 页面上所有可点击的控件都要真实可用，动态数据统一走服务端接口。
3. 用户身份、OpenAPI 等依赖抖音环境的能力，先做本地兜底并在代码中标清接入位置，不要臆造平台接口。
4. 完成后启动本地预览服务，告诉我兴趣卡和落地页的预览地址。
```

## 04｜打包交接：精简代码包 + 交接提示词

**关键原则：不要把整个本地工程直接打包上传！** 平台工程里已经自带了基础模板和依赖环境，整包上传很容易把原有配置覆盖坏。

正确做法是生成两样交接物：**`handoff.zip`** + **写给平台 AI 的交接提示词**：

```text
本地效果已确认，准备迁移到抖音 AI 工坊。请对照 interest_card_skills/ 中的规范帮我完成两件事：

1. 打包精简代码包 handoff.zip：
- 只放入本次开发的业务代码、DESIGN.md 和用到的素材文件，目录层级与 card-app/ 保持一致；
- 不要放入 package.json、node_modules、构建产物、密钥，也不要放入模板自带的基础配置；
- 压缩包内附一份 README.md，列出每个文件的放置位置，以及需要与平台现有模板合并的地方。完成后告诉我压缩包路径。

2. 输出一段发给「抖音 AI 工坊 AI」的交接提示词，写清以下信息：
- 作品玩法简介；
- 合并方式：先解压到临时目录，再按 README.md 合并到已有工程，不要重新初始化项目；
- 服务域类型（开放域 / 封闭域）；
- 需要平台接入的能力及代码中的具体接入位置；
- 需要转存为线上链接的图片素材；
- 卡片外框（标题、背景图、背景音乐）和落地页的补齐要求；
- 明确哪些视觉样式与交互已定稿，合并时不要改动；
- 合并完成后的预览自检清单。
```

## 05｜回平台上线：自动接入抖音能力并发布

1. **上传代码包与交接说明**：在抖音 AI 工坊对话框中上传 `handoff.zip`，粘贴外部 AI 生成的交接提示词并发送。
2. **等待平台 AI 自动合并与接入**：平台 AI 在保留原有工程骨架的前提下合并业务文件，并自动接入用户身份/OpenAPI/大模型能力、转存图片为线上链接、配置卡片背景与背景音乐等外框信息、补齐落地页。
3. **在预览器中核对微调**：在平台预览器中完整点按体验卡片和落地页，如有细节出入直接在对话框让平台 AI 微调。
4. **填写信息并发布**：进入「发布配置」，填好作品名称、简介并上传图标，确认发布即可提交参赛。
